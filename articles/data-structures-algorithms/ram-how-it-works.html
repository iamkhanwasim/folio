RAM and How It Works

March 2020

RAM (Random Access Memory) is the working memory of a computer where data and programs are temporarily stored during execution. Understanding how RAM works is fundamental to writing efficient algorithms and choosing appropriate data structures.

RAM provides fast, temporary storage that the processor can access directly. Unlike storage drives, RAM is volatile - data disappears when power is lost. This trade-off enables the speed necessary for real-time program execution.

What is Random Access?

Random Access means you can access any memory location in constant time O(1), regardless of its position. This is different from sequential access where you must read through previous data first.

Think of RAM like a grid of mailboxes. Each mailbox has a unique address. You can go directly to mailbox 1000 without opening mailboxes 1-999 first. This is random access.

Memory Structure

RAM is organized as a linear array of bytes. Each byte has a unique address starting from 0:

Address Value (byte) Description
0x0000 01001010 First byte
0x0001 11010011 Second byte
0x0002 00110101 Third byte
... ... ...
0xFFFF 10101100 Last byte (64KB RAM)

How Data is Stored

Different data types occupy different amounts of memory:

  • char (1 byte): Stored in a single memory location
  • int (4 bytes): Stored across 4 consecutive memory locations
  • double (8 bytes): Stored across 8 consecutive memory locations
  • Arrays: Stored in contiguous memory blocks
  • Pointers: Store memory addresses (typically 4 or 8 bytes)

Memory Access Speed

RAM access is fast but not instant. Understanding access patterns helps optimize performance:

Access Time Characteristics:

  • Direct access: ~10-100 nanoseconds for any location
  • Cache hit: 1-10 nanoseconds (faster than RAM)
  • Cache miss: Must fetch from RAM (~100 ns penalty)
  • Sequential access: Benefits from cache prefetching

Why This Matters for Data Structures

Arrays:

Store elements in contiguous memory. Index access is O(1) because:

  • Element address = base_address + (index × element_size)
  • Direct calculation, no traversal needed
  • Cache-friendly due to sequential layout

Linked Lists:

Nodes can be scattered across memory:

  • Each node stores data + pointer to next node
  • Access requires following pointers: O(n)
  • Less cache-friendly due to random memory jumps
  • But flexible for insertions/deletions

Memory Addressing Example

Array element at index i:
address = base_address + (i × sizeof(element))

For an integer array starting at address 1000:

  • arr[0] is at address 1000
  • arr[1] is at address 1004 (1000 + 1×4)
  • arr[2] is at address 1008 (1000 + 2×4)
  • arr[n] is at address 1000 + n×4

Cache and Locality

Modern processors use cache memory (L1, L2, L3) to speed up RAM access. Two types of locality improve cache performance:

  • Temporal locality: Recently accessed data is likely to be accessed again soon
  • Spatial locality: Data near recently accessed locations is likely to be accessed soon

Arrays benefit from spatial locality. Linked lists do not. This is why array iteration is often faster than linked list traversal despite both being O(n).

Stack vs Heap Memory

Stack Memory:

  • Automatically managed
  • Fast allocation/deallocation
  • Limited size (typically 1-8 MB)
  • Local variables stored here
  • LIFO (Last In First Out) structure

Heap Memory:

  • Manually managed (malloc/free, new/delete)
  • Slower allocation/deallocation
  • Large size (limited by system RAM)
  • Dynamic data structures stored here
  • Can lead to fragmentation

Practical Implications

For algorithm design:

  • Prefer contiguous memory layouts (arrays) for read-heavy workloads
  • Use linked structures when insertion/deletion frequency is high
  • Consider cache effects for performance-critical code
  • Minimize memory allocations in tight loops
  • Be aware of memory limits when dealing with large datasets

Key Takeaways

  • RAM provides constant-time access to any memory location by address
  • Memory is organized as bytes with sequential addresses starting from 0
  • Data structures differ in memory layout affecting cache performance
  • Arrays are cache-friendly due to contiguous storage
  • Understanding memory helps choose the right data structure for the task
  • Stack and heap serve different purposes with different performance characteristics
