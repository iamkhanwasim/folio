Computational Complexity

March 2020

Computational complexity measures how algorithm performance scales with input size. It answers two fundamental questions: how much time does an algorithm take, and how much memory does it use? Understanding complexity helps choose the right algorithm and predict how code behaves with larger datasets. This is particularly important when selecting data structures for your programs.

Complexity is expressed using Big O notation, which describes the worst-case growth rate. Instead of counting exact operations, it focuses on how runtime or memory usage grows relative to input size. This abstraction makes it possible to compare algorithms independent of hardware or programming language.

Time Complexity

Time complexity measures how many operations an algorithm performs as input size increases. It focuses on the dominant factor that affects runtime. Different data structures have different time complexities for common operations like search, insert, and delete.

Common Time Complexities (from fastest to slowest):

  • O(1) - Constant: Operations take the same time regardless of input size
  • O(log n) - Logarithmic: Time grows logarithmically (binary search)
  • O(n) - Linear: Time grows proportionally with input size
  • O(n log n) - Linearithmic: Efficient sorting algorithms
  • O(n²) - Quadratic: Nested loops over the data
  • O(2ⁿ) - Exponential: Doubles with each additional input
  • O(n!) - Factorial: Trying all permutations

O(1) - Constant Time

Operations complete in the same time regardless of input size. Array access, hash table lookups, and simple calculations are O(1).

# Array access - O(1)
def get_first_element(arr):
    return arr[0]

# Dictionary lookup - O(1) average
def get_value(dictionary, key):
    return dictionary[key]

# Simple arithmetic - O(1)
def add(a, b):
    return a + b

O(n) - Linear Time

Time grows linearly with input size. Iterating through an array once is O(n).

# Linear search - O(n)
def find_element(arr, target):
    for item in arr:
        if item == target:
            return True
    return False

# Sum all elements - O(n)
def sum_array(arr):
    total = 0
    for num in arr:
        total += num
    return total

O(n²) - Quadratic Time

Common in nested loops where each element is compared with every other element. Performance degrades quickly with larger inputs.

# Bubble sort - O(n²)
def bubble_sort(arr):
    n = len(arr)
    for i in range(n):
        for j in range(0, n - i - 1):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
    return arr

# Check for duplicates - O(n²)
def has_duplicates(arr):
    for i in range(len(arr)):
        for j in range(i + 1, len(arr)):
            if arr[i] == arr[j]:
                return True
    return False

O(log n) - Logarithmic Time

Halves the problem size with each step. Binary search on sorted data is the classic example.

# Binary search - O(log n)
def binary_search(arr, target):
    left, right = 0, len(arr) - 1

    while left <= right:
        mid = (left + right) // 2

        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1

    return -1

Why O(log n) is fast:

  • Searching 1,000 items takes ~10 operations
  • Searching 1,000,000 items takes ~20 operations
  • Searching 1,000,000,000 items takes ~30 operations

Space Complexity

Space complexity measures how much additional memory an algorithm needs relative to input size. It includes variables, data structures, recursive call stacks, and temporary storage.

Common Space Complexities:

  • O(1) - Constant Space: Fixed amount of memory regardless of input
  • O(n) - Linear Space: Memory grows proportionally with input size
  • O(n²) - Quadratic Space: Creating 2D arrays or matrices

O(1) Space - Constant

Uses a fixed amount of memory. Variables don't scale with input size.

# In-place reversal - O(1) space
def reverse_array(arr):
    left, right = 0, len(arr) - 1
    while left < right:
        arr[left], arr[right] = arr[right], arr[left]
        left += 1
        right -= 1
    return arr

# Only uses two variables: left and right

O(n) Space - Linear

Creates new data structures proportional to input size. Common in recursion and when building output collections.

# Creating a copy - O(n) space
def double_values(arr):
    result = []
    for num in arr:
        result.append(num * 2)
    return result

# Recursive factorial - O(n) space due to call stack
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)

# Each recursive call adds to the call stack

Time vs Space Tradeoffs

Often there's a tradeoff between time and space. Caching results uses more memory but saves computation time. Understanding both complexities helps make informed decisions.

# Fibonacci without memoization - O(2ⁿ) time, O(n) space
def fib_slow(n):
    if n <= 1:
        return n
    return fib_slow(n - 1) + fib_slow(n - 2)

# Fibonacci with memoization - O(n) time, O(n) space
def fib_fast(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n

    memo[n] = fib_fast(n - 1, memo) + fib_fast(n - 2, memo)
    return memo[n]

# Trading O(n) extra space for exponential time savings

Practical Complexity Analysis

Real-world impact at scale:

  • 1,000 items: O(n) = 1,000 ops, O(n²) = 1,000,000 ops
  • 10,000 items: O(n) = 10,000 ops, O(n²) = 100,000,000 ops
  • 1,000,000 items: O(log n) = 20 ops, O(n) = 1,000,000 ops

Analyzing Complexity

Steps to determine complexity:

  • Identify loops: Single loop = O(n), nested = O(n²)
  • Check data structures: Hash table lookups = O(1), array search = O(n)
  • Look for recursion: Count recursive calls and depth
  • Drop constants: O(2n) becomes O(n)
  • Keep dominant term: O(n² + n) becomes O(n²)
  • Consider worst case: What happens with the largest input?

Common Pitfalls

  • Hidden complexity: String concatenation in loops can be O(n²)
  • Library functions: sort() is O(n log n), not O(1)
  • Nested operations: Loop containing a search = O(n²)
  • Recursive space: Call stack uses O(n) space for n recursive calls

Key Takeaways

  • Big O describes growth rate, not exact operations
  • Time complexity measures computational steps
  • Space complexity measures memory usage
  • O(1) and O(log n) are highly efficient
  • O(n) is acceptable for most problems
  • O(n²) and worse become problematic at scale
  • Analyze worst case to guarantee performance
  • Understand tradeoffs between time and space
