How Data is Stored in Memory

March 2020

Understanding how data is stored in memory is crucial for writing efficient programs. Different data types and structures occupy memory in different ways, affecting both performance and memory usage. This knowledge helps you make informed decisions when choosing data structures.

In Python, every value is an object stored in RAM. Unlike low-level languages, Python abstracts memory management, but understanding the underlying storage helps optimize code.

How Integers are Stored

Integers in Python are objects that store numerical values. Unlike C or Java where an int is 4 bytes, Python integers are variable-sized and can grow to accommodate any number.

import sys

# Small integer
small_num = 10
print(f"Size of 10: {sys.getsizeof(small_num)} bytes")  # 28 bytes

# Larger integer
large_num = 10000000000
print(f"Size of 10B: {sys.getsizeof(large_num)} bytes")  # 32 bytes

# Very large integer (Python can handle arbitrary precision)
huge_num = 2 ** 1000
print(f"Size of 2^1000: {sys.getsizeof(huge_num)} bytes")  # 160 bytes

Integer Storage Details:

  • Overhead: Python integer objects have ~24 bytes of overhead (object header, reference count, type info)
  • Value storage: The actual number stored in 4-byte chunks
  • Small integers (-5 to 256): Cached and reused to save memory
  • Arbitrary precision: Can store numbers of any size (limited by available memory)

How Characters and Strings are Stored

Strings in Python are sequences of Unicode characters. Each character is stored using a variable number of bytes depending on the encoding.

import sys

# Single character
char = 'A'
print(f"Size of 'A': {sys.getsizeof(char)} bytes")  # 50 bytes

# String storage
text = "Hello"
print(f"Size of 'Hello': {sys.getsizeof(text)} bytes")  # 54 bytes

# Longer string
longer = "Hello World"
print(f"Size of 'Hello World': {sys.getsizeof(longer)} bytes")  # 60 bytes

# Unicode character (requires more bytes)
emoji = "😀"
print(f"Size of emoji: {sys.getsizeof(emoji)} bytes")  # 76 bytes

# Check encoding size
print(f"'Hello' in UTF-8: {len('Hello'.encode('utf-8'))} bytes")  # 5 bytes

String Storage Details:

  • Overhead: ~49 bytes for string object metadata
  • ASCII characters: 1 byte each when stored
  • Unicode (non-ASCII): 2-4 bytes per character
  • Immutable: Strings cannot be changed in place, new string created for modifications
  • Interning: Identical strings may share memory

How Lists are Stored

Lists are stored as dynamic arrays. They maintain references (pointers) to objects, not the objects themselves.

List in Memory:
┌─────────────────────┐
│ List Object Header  │  (overhead: ~56 bytes)
├─────────────────────┤
│ [ptr] → Integer(1)  │  (8 bytes pointer)
├─────────────────────┤
│ [ptr] → Integer(2)  │  (8 bytes pointer)
├─────────────────────┤
│ [ptr] → Integer(3)  │  (8 bytes pointer)
├─────────────────────┤
│ [empty capacity]    │  (pre-allocated space)
└─────────────────────┘
import sys

# Empty list
empty = []
print(f"Empty list: {sys.getsizeof(empty)} bytes")  # 56 bytes

# List with 3 integers
numbers = [1, 2, 3]
print(f"List [1,2,3]: {sys.getsizeof(numbers)} bytes")  # 88 bytes

# List stores references, not values directly
a = [100]
b = [100]
print(f"Same size: {sys.getsizeof(a)} == {sys.getsizeof(b)}")  # Both 72 bytes

# Lists over-allocate to avoid frequent resizing
lst = [1]
for i in range(10):
    lst.append(i)
    print(f"Length: {len(lst)}, Size: {sys.getsizeof(lst)}")

List Storage Details:

  • Contiguous memory: Array of pointers stored sequentially
  • Each element: 8 bytes (pointer to object)
  • Over-allocation: Extra capacity to minimize resizing
  • Growth pattern: Approximately doubles capacity when full
  • Mixed types allowed: Each pointer can reference any object type

How Dictionaries are Stored

Dictionaries use hash tables for fast lookups. They store key-value pairs with significant overhead for the hash table structure.

import sys

# Empty dictionary
empty_dict = {}
print(f"Empty dict: {sys.getsizeof(empty_dict)} bytes")  # 232 bytes

# Dictionary with one entry
one_entry = {'a': 1}
print(f"Dict {a:1}: {sys.getsizeof(one_entry)} bytes")  # 232 bytes

# More entries
data = {'a': 1, 'b': 2, 'c': 3}
print(f"Dict with 3 items: {sys.getsizeof(data)} bytes")  # 232 bytes

# Dictionary expands when needed
big_dict = {f"key{i}": i for i in range(100)}
print(f"100 items: {sys.getsizeof(big_dict)} bytes")  # 4704 bytes

Dictionary Storage Details:

  • Hash table: Array of buckets for fast lookup
  • High overhead: Minimum 232 bytes even when empty
  • Each entry: Stores hash, key pointer, value pointer
  • Load factor: Resizes when ~2/3 full to maintain O(1) lookup
  • Ordered (Python 3.7+): Maintains insertion order

Memory Addresses and References

Python variables are references to objects in memory. Understanding this is crucial for understanding how data is stored.

# Variables are references
a = [1, 2, 3]
b = a  # b references same object as a

print(f"a's address: {id(a)}")
print(f"b's address: {id(b)}")
print(f"Same object: {a is b}")  # True

# Modifying through one reference affects the other
b.append(4)
print(f"a: {a}")  # [1, 2, 3, 4]

# Integers are immutable - assignment creates new object
x = 10
print(f"x address: {id(x)}")
x = 20
print(f"x new address: {id(x)}")  # Different address

Contiguous vs Non-Contiguous Storage

Contiguous Storage (Arrays/Lists):

  • Memory layout: Elements stored in adjacent memory locations
  • Access: O(1) by index using arithmetic
  • Advantages: Cache-friendly, fast iteration
  • Disadvantages: Resizing is expensive, insertion/deletion in middle is O(n)

Non-Contiguous Storage (Linked Lists, Trees):

  • Memory layout: Elements scattered, connected by pointers
  • Access: O(n) requires following pointers
  • Advantages: Efficient insertion/deletion, no resizing needed
  • Disadvantages: Cache-unfriendly, extra memory for pointers

Memory Overhead Comparison

import sys

# Compare storage efficiency
def compare_structures(n):
    # List of integers
    lst = list(range(n))

    # Tuple of integers
    tpl = tuple(range(n))

    # Set of integers
    st = set(range(n))

    # Dictionary with integers
    dct = {i: i for i in range(n)}

    print(f"\nStoring {n} integers:")
    print(f"List:  {sys.getsizeof(lst):,} bytes")
    print(f"Tuple: {sys.getsizeof(tpl):,} bytes")
    print(f"Set:   {sys.getsizeof(st):,} bytes")
    print(f"Dict:  {sys.getsizeof(dct):,} bytes")

compare_structures(1000)
# List:  8,856 bytes
# Tuple: 8,040 bytes (more compact)
# Set:   32,992 bytes (hash table overhead)
# Dict:  36,968 bytes (highest overhead)

Practical Implications

Choose based on your needs:

  • Need fast lookup? Use dict or set (accept memory overhead)
  • Memory-constrained? Use tuple instead of list when possible
  • Large datasets? Consider arrays from the array module (more compact)
  • Frequent modifications? Lists are better than tuples
  • Sequential access? Lists benefit from cache locality

Key Takeaways

  • Every Python value is an object with overhead for metadata
  • Integers have variable size and can grow arbitrarily large
  • Strings store Unicode characters using 1-4 bytes per character
  • Lists store pointers not values directly, in contiguous memory
  • Dictionaries use hash tables with significant memory overhead
  • Variables are references to objects, not the objects themselves
  • Different structures have different memory footprints - choose wisely
